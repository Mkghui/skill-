## ComfyUI-ZIQWH3 剧本创作

小说进、漫剧剧本出。中间那一层是**三套模型提示词各自的标准**——剧本好不好看是创作问题，提示词写不对是能不能生成的问题，这一层用 20 道确定性门守死。

| 交付 | 解决什么 |
| --- | --- |
| 分集剧本（场次 / 节拍 / 台词 / 语气） | 一集一分钟就是六十秒：台词按口播节奏折算、镜头按秒估时，写超写欠当场拦下 |
| Z-Image 文生图提示词 | 人物资产卡（左半身像 + 右三视图）、场景（分层 + 光影）、道具、每镜首帧——**一致性锚点**逐字复用的地方 |
| Qwen-Image 图生图提示词 | 在资产图上改出这一镜的动作 / 表情 / 换装 / 融合：**修改指令 + 保留从句 + 参考图分工**，三样缺一不可 |
| MiniMax H3 图生视频提示词 | 全局设定 + 分时段（0-2 / 2-5 / 5-8 秒）+ 稳定约束；五种模式与首尾帧对齐规则 |
| Word 文档 | 五章一体：人物 / 场景 / 道具 / 分集剧本 / 逐镜提示词，18 页量级，双击就能开 |

`{baseDir}` = 本文件所在目录。脚本 `{baseDir}/scripts/ziqwh3.mjs`，零依赖，`node` 直接跑。

**三类提示词的标准来源**（本项目立规矩的地方）：`E:\2.漫剧制作\提示词\` 下三个文件夹里的 docx 已逐条提炼进 `{baseDir}/references/`：

| 标准 | 提炼文件 |
| --- | --- |
| `1.z-image(文生图)\` 5 份（人物 / 场景 / 微表情 / 修仙人物 / 修仙场景） | `references/z-image-standard.md` |
| `2.qwen-image（图生图）\` 2 份（人与场景 / 打斗施法飞行炼丹） | `references/qwen-image-standard.md` |
| `3.minimaxH3（图生视频）\` 6 份（万能模板 / 文生视频 / 图生视频 / 首尾帧 / 参考生视频 / 专业导演版） | `references/minimax-h3-standard.md` |
| `E:\3.短剧\1.z-image(文生图)\zimage道具、武器、符箓、阵法、结界、修炼功法秘籍的提示词.docx` | `references/z-image-props-standard.md` |
| `E:\3.短剧\3.minimaxH3（图生视频）\6.MiniMax H3打斗施法提示词.docx` | `references/h3-action-standard.md` |

`E:\3.短剧\` 是与 `E:\2.漫剧制作\提示词\` **同源的标准目录**（13 份共享文件逐字节一致），只多上面那两份；两份都并进来了。

文件夹更新了就重新提炼一次——以那两个目录为准，不以本 skill 的记忆为准。

**边界（不做的事）**：不出图、不出视频、不提交任何生成任务、不配乐、不建 ComfyUI 工作流。做的是「把小说写成剧本 + 把三类提示词写对 + 校到过门 + 出 Word」。

### Step 0 — 定输入与范围

**输入**：小说正文（`.docx` / `.txt` / `.md`）。默认目录 `E:\2.漫剧制作\小说\`。

**输出**：默认写到 `E:\2.漫剧制作\剧情剧本\`，文件名 `<剧名>-EP<集号>-漫剧剧本.docx`（整个文件也可叫全稿名，见 Step 4）。

四件事先问清、写进 `params`（用户没指定就用默认并说明）：

1. 集数与单集时长——漫剧单集 1–2 分钟；1 分钟 ≈ 8 镜 × 8 秒
2. 画幅——16:9 横屏 / 9:16 竖屏，全剧统一
3. 题材与画风——`genre` 与 `visualStyle` 各一句话，`visualStyle` 决定跨镜一致性的总闸
4. H3 语言——`h3Format`：`zh`（默认，官方标准结构）/ `zh-en`（加英文镜像版）/ `en3`（英文三字段专业版）

### Step 1 — 读小说

```bash
node {baseDir}/scripts/ziqwh3.mjs readdoc <小说.docx> --range 1-200
```

带段号输出，按段分批读；一万三千段的长篇也只读你切给它的那一段。读的时候就该记下四张清单：**人物**（谁是主角、谁有转变弧、谁是功能性的）、**场景**（同一地点换时段的算一个）、**道具**（有特写、跨集出现、承载剧情的）、**爽点与钩子**。

### Step 2 — 建 manju.json

结构见 `{baseDir}/references/schema.md`（唯一数据契约），怎么写见 `{baseDir}/references/adaptation-pass.md`。顺序固定：

1. 先写 `characters` / `scenes` / `props` 的资产与**一致性锚点**——锚点写不具体，后面每一镜都会飘
2. 再写 `episodes`：每集的 `hook`、`suspense`、两个 ShotId——**钩子与悬念必须是具象画面，不是标签**
3. 最后逐镜写 `shots`：节拍流（动作 ⇄ 台词）+ 三段提示词 + `refs` 分工

**一次写几集**：默认一批 ≤ 3 集。剧本是全管线改得最凶的一层，小批量出、快拍板、再往下写。

三条容易踩的：**一镜只做一件事**（超过 4 个动作节拍生成必崩）；**台词单句一口气**（≤35 字，单镜 ≤秒数×5 字）；**每镜的提示词单独写**，只有锚点与画风是复用的，整集复制粘贴一定被门拦。

### Step 3 — 校验 ⛔ 不能跳

```bash
node {baseDir}/scripts/ziqwh3.mjs validate manju.json    # 22 道门（逻辑 11 + 提示词 11）
node {baseDir}/scripts/ziqwh3.mjs fix      manju.json --write   # 机械校正
```

`fix` 只干机械活：分时段标签归一化、补「字幕：无任何文字、水印、字幕。」固定行、缺稳定约束补模板原文、`Picture` 键归一化与重新编号、mode 简写归一化、秒数夹到 4–15、整行重复去重、补 `episodes` 条目与 `hookShotId/suspenseShotId`、`params` 缺省回落。**它不造内容**——`todo` 里列出来的（缺 hook、缺锚点、缺提示词）必须由你补写。

**有违规逐条修，改完重跑，直到 0 错。** 时长超了先砍动作节拍再压台词；欠了补戏不注水（加冲突不加寒暄）；钩子没落首镜就换首镜，或把钩子的具象写进首镜节拍。

门之外的**剧情逻辑**（因果、信息差、动机、能力边界、时间线……代码查不了）照着 `{baseDir}/references/adaptation-pass.md` 的十条自检清单过一遍，这是「自动校检剧情逻辑」里模型负责的那一半。

### Step 4 — 出 Word 与汇报

```bash
# 三段合一（默认）：一份 Word 装齐人物/场景/道具 + 分集剧本 + 每镜三段提示词
node {baseDir}/scripts/ziqwh3.mjs render manju.json \
  --docx 'E:\2.漫剧制作\剧情剧本\道祖重修记之人界篇·青石镇-EP01.docx'

# 分模型出稿：三段合一 + ①Z-Image / ②Qwen-Image / ③H3 各一份，共 4 份
node {baseDir}/scripts/ziqwh3.mjs render manju.json --split --docx '<同样的路径>'

# 只要某一个模型的稿
node {baseDir}/scripts/ziqwh3.mjs render manju.json --scope h3 --docx <out.docx>

# 纸型：默认 A4 横排，要竖排加 --page portrait
node {baseDir}/scripts/ziqwh3.mjs render manju.json --page portrait
```

**纸型默认 A4 横排**（`--page landscape|portrait`）——横排一行放得下更长的提示词，抄进 ComfyUI 更省事。

`--docx` 给的是**基名**（可带目录），实际文件名由它派生：`<基名>-漫剧剧本.docx` / `<基名>-①Z-Image文生图.docx` / `<基名>-②Qwen-Image图生图.docx` / `<基名>-③MiniMaxH3图生视频.docx`。不给就落在 manju.json 同目录、用剧名做基名。

**两种交付形态都给了**，按用户要哪种给哪种：一份合并稿适合通读与交付，三份分模型稿适合一个模型一台机器同时开工（每份只装那一段提示词，不夹别的）。

有错误时会拒绝出稿（要强出加 `--force`）。版式见 `{baseDir}/references/docx-format.md`：封面信息表 → 交付说明 → 一、人物设定 → 二、场景设定 → 三、道具设定 → 四、分集剧本 → 五、分镜提示词（每镜 ①②③④ 四块），提示词是等宽灰底整块，三击选中直接粘进 ComfyUI 节点。

汇报一句话说清：几集几镜、总时长 vs 目标、人物/场景/道具各几个、哪些门贴着容差边、Word 路径；没过门的地方明说，别含糊。

最终落地：

## 三类提示词的硬规则速查

写之前把这三张表当清单用，细节看对应的 reference。

**Z-Image（文生图）**——主体 + 细节 + 风格 + 画质四要素；人物必须是**资产卡**（三视图 / 立绘 / 大头照，纯白背景）；场景必须写光；微表情拆成肌肉变化 + **权重**（`上眼睑下垂:1.6` 或 `（1.6）`）+ 反向约束（`无张嘴、无泪流满面`）。

**Z-Image 器物资产（道具 / 武器 / 符箓 / 阵盘 / 秘籍）**——白描五要素：主体（**材质**）+ 环境 + 光影 + 风格 + 细节。必须写材质（黑金 / 羊脂白玉 / 泛黄宣纸 / 残破竹简）、必须写光效、必须交代它放在哪（置于 / 悬浮 / 平铺 / 背景）；**不许用「好看 / 厉害」这类抽象词**；建议 100–200 字，核心主体靠前。铺地 / 笼罩性的阵法与结界登记成场景（提示词要写符文 / 图腾 / 能量 / 流转），能攥在手里的才登记成道具。

**Qwen-Image（图生图）**——三样缺一不可：**修改指令**（Replace / Extend / Transform / Composite / 替换 / 合成）+ **保留从句**（Preserve / Keep / 保留 / 不变，要列具体项：面部、发型、身形、机位、光线）+ **参考图分工**（image 1 / 参考图 / 原图）。动作戏可套六件套：风格 + 景别 + 场景 + 时间 + 动作 + 物理反馈（火花 / 尘土 / 流光 / 气流）+ 画质。

**MiniMax H3（图生视频）**——默认 `h3Format: "zh"` 走官方标准结构：`全局设定`（主体 / 场景 / 风格 / 固定不变元素 / 镜头方式 / 声音 / 字幕）+ 三段 `0-2秒 / 2-5秒 / 5-8秒`（画面 / 人物动作 / 镜头 / 音效匹配 / 衔接要求）+ `稳定约束`。模式决定提示词必须写明什么：

| 模式 | 什么时候用 | 必写 |
| --- | --- | --- |
| `T2VA` | 纯文字原创（闪回、氛围镜） | 无需对齐句 |
| `I2VA` | 单图首帧，从该画面动起来 | 从**首帧 / 原图**启动，只做细微微动 |
| `FL2VA` | 首尾帧补帧（转场、动作切换） | 首帧起步、**尾帧**收束，首尾差异越小越丝滑 |
| `L2VA` | 只给尾帧反推 | 最终收敛到**尾帧** |
| `R2VA` | 多参考图（身份 + 场景 + 风格） | 每张**参考图**的唯一职责 |
| `en3` | 英文三字段专业版 | 逐字对齐句（I2VA / FL2VA / L2VA 各有固定首行）+ ≤7000 字符 |

动作镜（打斗 / 施法 / 飞行 / 炼丹 / 突破）另加一层：标 `actionShot: true` 后按 `h3-action-standard.md` 查四件事——**力因果链**（蓄力→传导→接触→反馈，不写动作会发飘）、**特效与视觉**（粒子 / 流光 / 剑气 / 能量，动作镜的冲击全靠这块）、**音效匹配写具体声响**（破空 / 碰撞 / 轰鸣 / 碎裂，只写音量不算）、**图生图写清景别与动作本体**（六件套：风格+景别+场景+时间+动作+物理反馈）。特效词堆到 6 个以上、或者三段里没有慢动作 / 定格收尾，都会给警告。
